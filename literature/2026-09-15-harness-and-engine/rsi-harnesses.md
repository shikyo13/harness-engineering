## A realistic self-improvement ladder for Zero Code

1. Memory CRUD with evidence gating (lessons from failures): already scoped in the memory spec, cheapest and lowest risk, no frontier model needed.
2. Skills distilled from successful tool chains, Voyager style, gated by automatic re-run verification: local model is sufficient if the verifier is deterministic.
3. Goal budgets, the QM "grind" pattern: a minimum wall-clock or token floor before the agent may give up, a small extension of the existing goal plugin, no frontier model needed.
4. A persistent REPL (JS or Python) so large intermediate outputs live as variables instead of context tokens: the single biggest token saver at 50 tok/s, local-model feasible, and the precondition for the next rung.
5. Persistent, resumable, messageable sub-agents (upgrade the task tool beyond one-shot dispatch): a real engineering lift but still local-feasible, and what makes rung 4 pay off, per Prime Agent.
6. Prompt and config optimization, GEPA or DSPy style, run on packages/zero-eval: needs a frontier model as judge or reflector even though the optimized target stays local, matching OpenJarvis's own recipe of a cloud model tuning a local stack.
7. Continual-harness-style online co-learning, rollouts relabeled by a frontier teacher and folded back into skills, memory, and prompt: needs a frontier teacher, and is validated so far only on a game domain, so treat as experimental for coding.
8. Harness code self-modification, Darwin Godel Machine style: an archive of harness and prompt candidates, sandboxed self-edit, evaluate, keep; needs the eval runner as a frozen fitness set first.
9. Keep the archive and rollback discipline for rung 8 non-negotiable: DGM keeps every candidate and its score so a bad self-edit is discarded, not kept.
10. DAgger-style test-time weight updates (fine-tuning the live model on its own recent trajectory) is the furthest rung: needs frontier-model supervision and direct weight access, so treat it as a research stretch goal, not a near-term target.

Rungs 6, 7, and 10 need frontier-model capability, as judge, teacher, or optimizer, even when the improved target stays local. Rungs 1 through 5, 8, and 9 need only the local 125B-A6B model plus engineering.
