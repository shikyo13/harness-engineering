The repo is a **docs-and-issues surface, not a source repo**. Full file inventory (7 content files + 5 PNGs + 1 GIF):

No source code, no `docs/` directory, no config JSON schemas, no SDK package, no lockfiles, no CI. `git rev-list --count HEAD` = 1 (squashed initial commit); one branch (`main`), one tag. **Everything architectural below comes from changelog prose, my black-box probes, and the published GitHub Releases API for dates.**

Install path (published): no npm, no brew — `curl -fsSL https://antigravity.google/cli/install.sh | bash`. I inspected the 242-line script **[observed]**: it resolves a per-platform manifest from `https://antigravity-cli-auto-updater-974169037036.us-central1.run.app/manifests/<platform>.json` (Cloud Run service), verifies SHA-512, installs a **single flat native binary** to `~/.local/bin/agy`, strips macOS quarantine, then hands off to `agy install` for shell setup; supports `--dir`; platform matrix darwin/linux/windows × amd64/arm64 + linux-musl + Android/Termux (bionic). Binary **self-updates in background during regular runs** (script comment + `agy update` subcommand).

## 5. Reconstructed architecture and transitions (classified)

- **Agent engine**: proprietary, closed, Go, built inside google3 **[observed P14]**. Changelog calls it the same "Shared Core Agent Engine" as Antigravity 2.0 desktop **[published: README integration table + "improvements automatically apply to both"]**; binary corroborates shared machinery (Hub/desktop strings, identical step-type vocabulary, `.system_generated/{worktrees,subagents}` dirs, desktop SQLite import 1.0.4) **[inferred]**. The engine loop is called `BattleMode` internally with durable step trajectories, hooks observing turn invocations, and "invocation limits" **[inferred; changelog 1.1.10 "hit the invocation limit", 1.1.6 hook notes]**. Loop internals (prompt assembly, tool-call accounting) unavailable; `NO_TOOL_CALL` as a surfaced failure with self-correction (1.2.4) implies a tool-call-driven continuation **[documented-only]**.
- **Relation to desktop**: same engine, bidirectional settings sync, session export GUI←→CLI, shared permission merge (1.0.5), shared `~/.gemini/config`, desktop-aware workspace trust (1.3.0), unpin/unread side-effect fix on CLI start (1.2.7) — **one product family with two frontends** **[published claims; strongly corroborated by binary strings]**. Mechanism of sharing (shared library vs shared backend service) unresolved; gRPC endpoints to `v1internal` services suggest a server-side component participates in inference and language services **[inferred]**.
- **Long-running / async workflows**: execution modes cycled (request-review default since 1.1.0; `auto` added 1.3.5 with a separate reviewing agent for sandbox escapes **[observed P13]**); unlimited default headless timeout (1.2.6) with `--print-timeout` cap and background-task drain before exit (1.1.28/1.2.9); daemon background tasks (dev servers) that outlive turns; `schedule` tool with timers + `MaxIterations` wake conditions; `manage_task` kill/list; `/tasks` drawer; queued messages with an explicit `Queue | Send Immediately` config (`queuedMessages`) — Send-Immediately = mid-turn steering, matching Zero Code's steer vocabulary; `/btw` side questions on a side trajectory; `/goal` unlimited goal loop (1.0.14); auto-resume of conversations with active turns after restart (1.2.4). Interruption: Esc twice-pattern, ctrl+c cancel-then-exit (1.0.11), interruption from a remote controller counted equally (1.2.5).
- **Multi-agent**: first-class subagents — `invoke_subagent`, runtime `define_subagent` (Markdown definitions), `manage_subagents list|kill|kill_all`, `send_message`, `manage_inbox`, `@<subagent>` addressing (1.2.9), nested grandchild trajectories relayed to root (1.1.1), workspace modes per subagent (`branch`/`share` materialized as isolated Git worktrees, fixed 1.3.3), `self` subagent inheriting parent config (1.1.22), subagent model tiers (`model: inherit|flash|pro`), roster auto-injected into any agent listing `invoke_subagent` (1.2.5). ## 7. What Zero Code should learn

1. **The machine interface is the product surface for harnesses.** Google spent ~5 weeks (1.1.8→1.1.15) turning `-p` into: closed-vocabulary NDJSON steps both ways, per-tool `tool_info`, per-subagent `log_uri`+`conversation_id` for trajectory correlation, schema-enforced results, canonical `AGY_ERROR` with retryability, meaningful exit codes, `denied_actions`, and quota-free read-only slash commands. Zero Code's `zero-eval` and any external SDK should match this contract exactly; "stable `step_type` discriminator" is the single most quotable design decision here.
2. **Steer/queue is a supported user-facing config, and its edge cases are changelog fodder.** `queuedMessages: queue | send-immediately` plus the 1.3.1 bug (send-immediately silently queued whenever an artifact write happened mid-turn) and 1.2.14 (failed send returns to queue, never lost) are exactly the failure classes Zero Code's durable steer/queue vocabulary (V2) should have named regression tests for before launch.
3. **Two-execution-path debt is industry-standard and Google took a headline fix for it** (1.1.17 "single execution path, consistent tool/hook/prompt behavior"). Reinforces baseline finding 1: finish V1→V2 convergence, and make the convergence entry quotable.
4. **Plan/artifact approval must be orthogonal to permission bypass.** 1.3.2 strips `--dangerously-skip-permissions` of plan auto-approval. Zero Code should never let `--dangerously-skip-permissions`-style flags collapse its plan-review or checkpoint gates.
5. **Soft tool deprecation**: retire legacy tools from the default set while keeping them opt-in for custom agents that name them (1.2.7) — the safe rename path for Zero Code's four overlapping tool-reach layers.
6. **Context budget partitioning beats global compaction**: a fixed rules budget (20k) that cannot evict skills/subagents/MCP, compaction budgets sized from the model's full window, reclaimable-bytes accounting for truncation, and a user-triggerable `/compact`. These map directly onto Zero Code's compaction/pressure-note work as testable invariants.
7. **Agent-as-reviewer is arriving**: Auto mode (1.3.5) routes sandbox-escaping commands through a *separate reviewing agent*. A cheap model judging risk before irreversible actions is the direction the permission layer is heading; Zero Code's tree-sitter bash permissions could gain exactly this second lane.
8. **Persistence format as a product decision**: SQLite + FTS5 + WAL + lazy step headers + snapshot checkpoints made multi-thousand-step resumes fast and made sessions transferable to the desktop GUI. Zero Code's shadow-git + SQLite direction is validated; FTS5 conversation search (`@conversation:` with 2 s local fallback, 1.3.4) is a cheap, concrete feature to copy.
9. **Subagent worktree isolation with named workspace modes (`branch`/`share`) and roster injection into the system prompt** (1.2.5) is a clean, declarative multi-agent ergonomics package worth mirroring in V2 subagent design.
10. **Distribution posture**: single signed self-updating binary + background auto-update + `agy update` + sha512 manifests costs Google a stream of CPU-quirk changelog entries (AES-NI, ARM64, musl, Termux) — the price of zero-dependency reach; if Zero Code ever ships a native/desktop SEA build, budget for that bug class.
11. **Changelog as engineering culture artifact**: behavior-level, user-voice prose with near-daily cadence; every fix names the symptom and the recovery. Cheap competitive weapon; Zero Code's release notes could adopt the "Fixed … which previously … ; it now …" register verbatim.
