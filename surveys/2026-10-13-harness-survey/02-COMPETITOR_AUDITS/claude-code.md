# 02 — Competitor audit: Claude Code (Anthropic, closed-source harness)

Audited 2026-10-13. Two evidence planes kept separate throughout: (A) the public GitHub repo at head `b0b7bed98203`
("chore: Update mods/"), and (B) black-box probes against the installed native CLI `claude` v2.1.296
(Mach-O arm64, signed-in subscription account, `apiKeySource: "none"`). Classification tags:
**[implemented+verified]** (public source), **[published-docs]** (repo text: changelog/help/mods README),
**[experimentally observed]** (my probes on this machine), **[unavailable]**.

## 2. Published repo findings

### 2.1 The mods/ folder — the internal architecture, self-published
A "mod" is a plugin whose behavior lives in a `register(on, options)` hooks module hooking **the engine's own
events as functions `($, e, next)`**; four ship inside the binary and their source is published as-built
(`mods/README.md`). This is an SDK that mirrors internals almost verbatim [implemented+verified]:

- **`$` engine nouns** (`CoreEngineInterface`): `agent audio clock command config desktop env fs http mcp mobile
  model plugin process prompt session settings store terminal tool turn ui vscode` — plus plugins may **add nouns
  to `$` in the `engine.create` fold** (telemetry mod does exactly that to make built-in analytics a plugin).
  Surfaces are first-class: terminal, desktop, vscode, mobile; UI is a declarative JSX tree the plugin draws via
  `$.ui.resolve(e)` element tables, panes, blits, toasts, notices, dialogs.
- **Engine event registry** (`EngineEventOf`, 40 events): `engine.create`, `plugin.register`, `session.start/
  append/attach/detach/end/receive/compact/measure`, `turn.start/step/complete`, `prompt.submit/edit/fill/compose/
  section/context/attachment/suggest`, `tool.call`, `tool.check`, `tool.describe`, `config.describe/set`,
  `command.describe/run`, `agent.offer/spawn`, `skill.prompt`, `attribution.text`, `ui.render/resolve/open/close/
  press/input/select/scroll/focus/message/log`. Hooks are an onion: `next(e)` runs hooks beneath, then core
  (permission prompt, tool execution); returning while `next` is pending aborts what runs beneath.
- **Classic hook events folded in as `classic.<Event>`** — 34 of them, far beyond the documented
  PreToolUse/PostToolUse/Stop set: `PermissionRequest`, `PermissionDenied`, `PostToolBatch`, `PostToolUseFailure`,
  `PreCompact`, `PostCompact`, `PreModelSwitch`, `PostModelSwitch`, `TaskCreated`, `TaskCompleted`, `TeammateIdle`,
  `SubagentStart/Stop`, `SessionStart/End`, `Setup`, `InstructionsLoaded`, `UserPromptSubmit`,
  `UserPromptExpansion`, `MessageDisplay`, `Notification`, `Elicitation(+Result)`, `FileChanged`, `CwdChanged`,
  `DirectoryAdded`, `ConfigChange`, `WorktreeCreate/Remove`, `StopFailure`. Result vocabulary includes
  `decision: block`, `continue: false` + `stopReason`, `additionalContext`, `sessionTitle`,
  `suppressOriginalPrompt`, `updatedMCPToolOutput`.
- **Built-in tool contracts are typed in the `.d.ts`** (`BuiltinToolInputs`/`BuiltinToolResults`) — see §4.2.
- **A plugin test harness** that runs against the *engine's own* `$` with the world beneath mocked per-noun
  (`claude plugin test mods/diff`), and `claude plugin validate` that statically reports what a module hooks and
  calls. Tiering is explicit: mods seat at `builtin`/outermost tiers.
- **sec-default** [implemented+verified] is Anthropic's own org-security mod: from the outermost seat it holds a
  `deny`/`ask` decided by rules, classic hooks, or org policy **whole over what user-tier hooks do** (a verdict
  *ceiling* — user hooks cannot loosen org decisions, only tighten), refuses user-tier `tool.register` under an MCP
  allowlist, blocks writes to policy-relevant env vars (`NODE_OPTIONS`, `DYLD_INSERT_LIBRARIES`, `LD_PRELOAD`,
  proxies). Their hardening story: managed settings + policy tier + tiered hook onion, dogfooded as a plugin.
- **diff** builds the entire `/diff` pane as a mod (git probing + a hand-drawn terminal UI); **agents-md**
  implements AGENTS.md compatibility as an option over CLAUDE.md placement ("placed and framed exactly as the
  engine places CLAUDE.md, nested ones on a Read" — i.e. **nested CLAUDE.md files load lazily when Read touches
  that directory**).

### 2.2 Changelog (8,789 lines) as behavior spec — highlights used below [published-docs]
- **Todo/task tools are model-gated**: `TodoWrite` + `TaskCreate/Get/Update/List` are *removed* on Opus 4.8+,
  Sonnet 5, Fable 5, Mythos 5+ ("model doesn't need them"), bringable back with `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`.
- **Deferred tools + ToolSearch**: many tools (Grep, Glob, WebSearch/WebFetch, TaskOutput, MCP tools) ship as
  *deferred definitions*; model loads them via `ToolSearch(query, max_results)`; heavy engineering on cache
  interaction (mid-session MCP adds as deferred deltas "which broke prompt-cache reuse"; `--resume` cache-miss
  fix; deferred schemas surviving compaction; global system-prompt caching with ToolSearch).
- **Auto-compact is per-model-window**: `/autocompact auto|100k–1M`; Sonnet 5 auto-compacts ~967K of its 1M
  window; Opus/Fable compact shortly before 1M; "recovery compaction" on oversized contexts; advisor-tool turns
  were once double-counted against the window; fallback that drops 1M→200K is surfaced to the user.
- **Plan mode** persists across `--resume/--continue`, fork subagents inherit parent's plan mode and cannot exit
  it; **auto mode** has a classifier ("safety review") that can approve otherwise-prompting calls; `dontAsk`
  mode denies silently.
- Session forking (`--fork-session`, `--session-id` + `--resume`), fork lineage preserved across compaction.
- Massive platform surface in 2.1.29x: cloud sessions, self-hosted runners, Claude Tag (Slack), artifacts,
  `ultrareview` (cloud multi-agent review), gateway (enterprise auth/telemetry), background sessions (`--bg`,
  attach/logs/stop/respawn), worktrees (`-w`, `--tmux`), cron/wakeup scheduling tools, OpenTelemetry export,
  `CLAUDE_CODE_TRANSCRIPT_LOCAL_GC` (transcript garbage collection!).

### 2.3 Extension surface = architecture mirror
Plugin = `.claude-plugin/plugin.json` + `commands/` (markdown slash commands) + `agents/` (markdown agents with
`name/description/tools/model/color` frontmatter) + `skills/` (`SKILL.md`, name/description frontmatter,
progressive `references/`) + `hooks/hooks.json` (classic events and/or a `.ts` hooks module) + `.mcp.json`.
Output styles (deprecated natively) are reimplemented as SessionStart-injection plugins; `ralph-wiggum` implements
an autonomous loop plugin by **refusing Stop** (`continue: false` + re-prompt) — exit conditions are policy, not
hardwired. Devcontainer firewall + `.github/egress-firewall.yaml` + `--permission-mode auto` show their own CI
running Claude with three layers: network allowlist, runner firewall, permission classifier.

## 4. Reconstructed architecture

### 4.1 Agent loop [implemented+verified events; partially observed]
Per user turn: `prompt.submit` (hooks can rewrite/expand: `prompt.edit`, `UserPromptExpansion`) → durable
append (`session.append`; engine-injected rows exist) → `turn.start` → provider calls each annotated
`turn.step` (transcript rows carry `requestId`, `apiBlockIndex`, `requestedModel`, `effort`, `perTurnEffort`,
`advisorModel`) → tool batches per assistant message (parallel calls share one `requestId` — **observed**) →
each call through `tool.call` onion → `tool.check` decision chain ("rules, mode, the tool's own check, PreToolUse
decision"; `$.tool.check` runs the chain without executing) → `turn.complete` → `Stop` (hooks may
`continue:false` to prevent exit — the ralph-wiggum loop). Exit conditions: model `end_turn`, Stop-hook
continuation, `--max-turns`, `--max-budget-usd`, `preventContinuation`, interrupt capabilities
(`interrupt_receipt_v1`). Rate-limit events and `task_summary`/`post_turn_summary` appear in the headless stream.
Advisor turns exist (`advisorModel` rows; server-side advisor consulted roughly per turn) [observed, semantics
unavailable].

### 4.2 Tool design [implemented+verified (.d.ts) + observed]
Edit is classic exact-match `old_string`/`new_string` + `replace_all` (no fuzzy matcher published; failures are
fed back to model — observed error rows exist but semantics **unavailable**); Read: `offset/limit/pages` +
`allow_large` (changelog); Bash: `timeout`, `run_in_background`, `dangerouslyDisableSandbox` (sandbox on by
default; PowerShell twin); **Agent**: `description`, `prompt`, `subagent_type`, model alias,
`run_in_background`, `name`+`team_name` (named agents/teams!), `mode` (inherits any permission mode incl. plan),
`isolation: "worktree" | "remote"` (subagent can run in a git worktree or cloud). Agent result is a typed record:
usage, `toolStats`, `handback: send|flagged|withheld`, worktree path/branch, async launch variant.
`SendMessage` (agent↔agent and hand-back resume), `Monitor`, `Cron*`/`ScheduleWakeup` (durable prompts on a
clock), `Workflow` (scripted multi-agent DAG with `resumeFromRunId`), `ToolSearch` (lazy tool loading),
`ReportFindings` (structured review output), `Skill` (`{skill,args}` — skills are model-invoked tools),
WebFetch(url+prompt)/WebSearch. MCP tools namespaced `mcp__server__tool`, manifests + `tools_list_changed`
capability over the SDK.

### 4.3 Context management [observed + published-docs]
Context is **assembled from typed attachments**, visible in transcript JSONL: `instructions` (CLAUDE.md — root
eager, nested lazily on Read per agents-md mod), `environment`, `date`, `model`, `session_context`, `skill_listing`,
`agent_listing_delta`, `mcp_instructions_delta`, `deferred_tools_delta`, `prompt_snapshot`, `total_tokens_reminder`
(context-pressure reminders), `credential_org`, `remote_session_change`. Engine exposes the pipeline as
`prompt.section/context/attachment` events with **cached answers invalidated explicitly** (`$.ui.invalidate`),
plus `--system-prompt-snapshot` and `--exclude-dynamic-system-prompt-sections` to defend the cache. Caching is
real and aggressive: 1h ephemeral writes + large reads observed on turn one of a trivial prompt. Compaction:
`/compact` + per-model auto-compact windows (observed flag; 967K-of-1M threshold per changelog), `session.compact`
event, Pre/PostCompact hooks, compaction preserves fork lineage and (after fixes) deferred tool schemas;
`CLAUDE_CODE_TRANSCRIPT_LOCAL_GC` prunes saved transcripts.

### 4.4 Sessions [observed]
JSONL per session under `~/.claude/projects/<dashed-abs-path>/<uuid>.jsonl`; envelope fields include `parentUuid`
(DAG), `isSidechain`, `userType`, `entrypoint`, `cwd`, `sessionId`, `version`, `gitBranch`, `timestamp`, plus
typed rows: `user` (with `permissionMode`, `promptSource`, `turnOrigin`, `turnPosition`, `promptId`), `assistant`
(with `wireToolInputs`, `requestId`, `advisorModel`, `effort`), tool-result users carrying `permissionDecision`
and `toolUseResult`, `attachment`, `lastPrompt`, `queue-operation` (**durable prompt-queue rows** — steering is
durable, not just in-memory), `cost-state` (cumulative $/tokens/lines per session), `file-history-snapshot`,
`atis-latch`, `system` (hook summary rows: `hookCount/hookInfos/hookErrors/hookAdditionalContext/
preventedContinuation/stopReason`). Resume: `-c`/`-r`/`--session-id`; fork: `--fork-session` (+ custom id);
undo store separate (`file-history` per-session `@vN` content-addressed versions). Subagent transcripts are not
inline in the parent JSONL. `__store.db` mirrors messages for some server feature [unavailable].

### 4.5 Subagents & skills [observed + implemented+verified format]
`.claude/agents/*.md` / `--agents` JSON / plugin `agents/` all yield the same definition (frontmatter
name/description/tools/model[/color/tools allowlist]). Built-ins include Explore/Plan. Isolation options: fresh
context (default; hand-back envelope with anti-authority-forgery framing), `worktree`, `remote`; resumable by
agentId via SendMessage; backgrounded; teams by name; forked subagents inherit plan/dontAsk mode and can't exit
it. Skills = `SKILL.md` (name/description drives model-side auto-invocation listing; `Skill` tool loads full
text; `context: fork` exists per changelog; synced from claude.ai). Hooks see `SubagentStart/Stop`,
`TaskCreated/Completed`, `TeammateIdle`.

### 4.6 What the extension surface reveals
The engine is an **event-sourced hookable kernel**: everything (including Anthropic's own telemetry, diff pane,
security policy, AGENTS.md compat, loop plugins, output styles) rides the same plugin API; the SDK surface
(`$` nouns, event onion, element tables, tiers, `claude plugin validate`, engine-native test runner) is the
internal architecture with the private parts hidden behind `CoreEventOf` vs plugin nouns. Permission decisions
form a lattice with an org-controlled ceiling above user hooks. Feature flags (GrowthBook/Statsig) drive
behavior per user/org; cloud (sessions, runners, artifacts, advisor, ultrareview) is a first-class peer of local,
not an afterthought.

## 5. Strengths
1. Hookability as the product architecture — 40 kernel events + 34 hook events, onion semantics with abort and
   verdict rewriting; their own features are plugins, so the API is honest.
2. Prompt-cache engineering: sectioned prompt with invalidation registry, system-prompt snapshotting, dynamic-
   section hoisting, deferred tools to keep the stable prefix small, per-model compaction windows, cache-aware
   resume fixes tracked in changelog.
3. Structured tool contracts for every built-in tool (typed inputs AND outputs, incl. subagent usage/toolStats),
   structured output via `--json-schema`, and typed hand-back envelopes that defuse subagent prompt injection.
4. Model-adaptive tool surface (todo tools removed for newer models; deferred loading) — they tune the harness to
   the model instead of one-size-fits-all.
5. Durable session artifacts: parentUuid DAG, queue-operation rows, permissionDecision per call, cost-state,
   content-addressed file-history, fork lineage surviving compaction.
6. Security layering: hook tiers with org ceiling, pinned env vars, `--bare/--safe-mode/--restricted`, sandboxed
   Bash, egress-firewalled own CI with permission classifier; policy-as-files (MDM examples).
7. Changelog discipline: 8.8k lines of behavior-visible notes — effectively a public spec rivals lack.

## 6. Weaknesses / costs
1. Still closed core: exact loop scheduler, permission evaluator, compactor prompt, advisor, Edit-failure
   feedback remain **[unavailable]**; the `.d.ts` documents interfaces, not algorithms.
2. Complexity pressure on users: ~90 slash commands, 28+ tools, 4 hook config generations coexisting (settings
   commands vs hooks modules vs mods), env-var feature gates, per-model quirks; `--bare/--safe-mode/--restricted`
   exist because customization breaks sessions often enough.
3. Experiment-driven behavior (Statsig/GrowthBook caches) means documented behavior can silently differ per
   account/version; version drift is real (2.1.277 typed API vs 2.1.296 runtime).
4. Self-reported tool list by the model is unreliable (P2 hallucinated the registry); correctness depends on
   harness-side `init`/registry, which weaker clients must consume carefully.
5. Prompt-cache optimization shows visible cost of cache-stability hacks: prompt-snapshot staleness windows,
   compaction invalidating the snapshot, deferred-tools regressions repeatedly fixed (schemas lost on compact,
   64KB hang, resume cache-miss).
6. TodoWrite removal on newest models outsources plan-state to model judgment — no durable task ledger by
   default on exactly the models the company ships (opt-in env var).
7. Subagent transcripts not written inline to the parent session file — observability of sidechains from disk
   requires the stream flags (`--forward-subagent-text`) instead of persisted state.

## 7. What Zero Code should learn
1. **Publish a typed event contract of your own** the way `/plugin-types` does. Zero's V2 (SessionExecution,
   provider-turn allowance, steer/queue vocabulary) is internally similar; an exported `.d.ts` event/noun map
   would make the architecture legible and third-party-extensible, and forces coherent naming.
2. **Make your own features ride the extension API** (telemetry, diff, security as plugins/mods). Anthropic's
   mods folder proves dogfooding the plugin bus keeps it honest; Zero's telemetry ledger + shadow-git + repomap
   could seat on one onion bus with tiers + a policy ceiling.
3. **Verdict-ceiling permission lattice**: rank decisions (deny > ask > allow across sources), managed/policy
   hooks run first and their deny is final; user hooks may tighten but never loosen. Cheap, powerful, and it is
   exactly what Zero's permission rules + V2 lack for org/managed contexts.
4. **Cache-stability as a first-class engineering axis**: snapshot the rendered system prompt per conversation,
   move volatile sections (cwd/env/git) into the first user message, keep lazy tools out of the stable prefix —
   Zero already freezes prefixes; add snapshot-on-resume and volatile-section hoisting, and expose them as flags
   like `--system-prompt-snapshot` / `--exclude-dynamic-system-prompt-sections`.
5. **Deferred tool loading with ToolSearch** to fight tool-census bloat: Zero finding #6 (four overlapping
   "reach the right tool" layers) converges toward exactly this; commit to ONE mechanism (lazy registry + search
   tool + delta attachments) instead of registry+aliases+tool_search+code-mode in parallel.
6. **Model-gated tool surfaces**: adapt the exposed tool set to the selected model (drop todo tools for strong
   models) rather than global flags; keep an escape hatch env var.
7. **Structured, self-describing subagent hand-backs**: typed result records (usage, tool stats, handback mode)
   plus an anti-injection envelope that denies subagent text user authority and defends the frame. Zero's
   subagent story should copy this verbatim, and persist sidechain rows to the session store (they don't — a gap
   to beat them on).
8. **Durable-queue + turn-position transcript** (queue-operation, permissionDecision, cost-state, turnOrigin/
   turnPosition rows): matches Zero's V2 durable `session_input` design — validate that design against evidence
   that the market leader ships exactly this, and make the JSONL contract explicit.
9. **Changelog-as-spec**: publish per-release behavior notes granular enough to be auditable; it is the single
   most useful public artifact in the Claude Code repo and costs only discipline.
